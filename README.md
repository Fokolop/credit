# Техническое задание на разработку программного комплекса «Выдача кредитов в банке»

## 1. Основание для разработки

1. Основанием для данной работы служит договор № 1234 от 10 марта 2003 г.
2. Наименование работы: «Модуль автоматизированной системы выдачи кредитов в банке».
3. Исполнители: ОАО «Лаборатория создания программного обеспечения».
4. Соисполнители: нет.

## 2. Назначение разработки

Создание модуля для автоматизации процесса оценки кредитоспособности заемщиков и оперативного принятия решений о выдаче кредитов в банке.

## 3. Технические требования

### 3.1. Требования к функциональным характеристикам

#### 3.1.1. Состав выполняемых функций

Разрабатываемое ПО должно обеспечивать:
- Сбор и анализ информации о кредитной истории заемщиков из внутренней базы данных банка
- Сбор и анализ информации с внешних кредитных бюро
- Автоматизированную проверку анкетных данных и документов заемщиков
- Предварительный анализ информации на предмет соответствия кредитным требованиям банка
- Формирование автоматических рекомендаций по одобрению/отклонению кредитной заявки
- Отображение текущего статуса кредитных заявок в реальном времени
- Визуализацию информации по кредитному портфелю:
  - Текущие показатели выданных кредитов
  - Статистика за прошедшие сутки, неделю, месяц
  - Аналитические отчеты по просроченной задолженности
- Возможность ручного пересмотра автоматических решений опытными кредитными специалистами

#### 3.1.2. Организация входных и выходных данных

Исходные данные в систему поступают в виде анкетных данных заемщиков, сканированных копий документов и информации из кредитных бюро. После анализа поступившей информации система формирует кредитное решение. Возможна также ручная корректировка решений кредитными менеджерами.

Основной режим использования системы - ежедневная работа в течение рабочего дня банка.

### 3.2. Требования к надежности

Для обеспечения надежности необходимо:
- Проверять корректность вводимых данных
- Обеспечивать резервное копирование базы данных
- Реализовать систему восстановления после сбоев

### 3.3. Условия эксплуатации и требования к составу и параметрам технических средств

Для работы системы должен быть выделен ответственный оператор. Требования к составу и параметрам технических средств уточняются на этапе эскизного проектирования системы.

### 3.4. Требования к информационной и программной совместимости

Программа должна работать на платформах Windows 98/NT/2000 и интегрироваться с существующей банковской системой.

### 3.5. Требования к транспортировке и хранению

Программа поставляется на лазерном носителе информации. Программная документация поставляется в электронном и печатном виде.

### 3.6. Специальные требования

Программное обеспечение должно иметь дружественный интерфейс, рассчитанный на пользователя средней квалификации.

Ввиду объемности проекта задачи предполагается решать поэтапно, при этом модули ПО, созданные в разное время, должны предполагать возможность наращивания системы и быть совместимы друг с другом.

Язык программирования - по выбору исполнителя, должен обеспечивать возможность интеграции с банковскими системами и защиту конфиденциальной информации.

## 4. Требования к программной документации

Основными документами, регламентирующими разработку будущих программ, должны быть документы Единой Системы Программной Документации (ЕСПД): руководство пользователя, руководство администратора, описание применения.

## 5. Технико-экономические показатели

Эффективность системы определяется удобством использования системы для автоматизации процесса выдачи кредитов, снижением времени обработки заявок, уменьшением количества ошибок и повышением качества кредитного портфеля банка.

## 6. Порядок контроля и приемки

После передачи Исполнителем отдельного функционального модуля программы Заказчику, последний имеет право тестировать модуль в течение 7 дней. После тестирования Заказчик должен принять работу по данному этапу или в письменном виде изложить причину отказа от принятия. В случае обоснованного отказа Исполнитель обязуется доработать модуль.
